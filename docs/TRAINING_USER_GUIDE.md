# 如何使用个人训练台

入口是网站的 `/training`。登录所有者账号后使用；正式记录在 GitHub 的 `content/training/state.json`。没有记录时页面为空，不会替你创建学习成绩。公开仓库里的文件可被访问，不要提交真实账号、Token 或隐私信息。

## 第一次：提交一份自己的练习

1. 按 `projects/beginner-api-lab/README.md` 准备环境，按 `EXERCISES.md` 编写 `tests/test_registration_practice.py`，不要复制示范测试冒充作业。
2. 在正常实现上运行独立测试，再用 `selfcheck.py tests/test_registration_practice.py` 分别验证三种故障。环境错误、收集错误、skip 不算检出。
3. 把独立测试提交本仓库的 GitHub 分支，复制完整 commit SHA；网页检查该版本存在指定测试文件，不执行或判定代码质量。
4. 在“练习验收”填写基线和三种故障的实际结果、复盘以及可选的本仓库 CI 运行链接。确认公开仓库提示，再提交。
5. 看见“已提交到 GitHub”与 commit 链接才算正式保存。刷新后可核对记录；原知识点勾选不会改变。

练习结果始终标为“学习者自报，未自动验真”。CI 链接只是记录，未读取核验 CI；代码存在、测试全绿都不等于掌握。更正练习结果时提交新的尝试，旧尝试保留；推荐使用最新尝试。

## 第二次：从错误中选一个复习问题

从笔记或排障详情点“加入复习”。手动确认一个问题及参考答案，并选择概念解释或代码/排障重做。每篇来源最多一张卡；创建当天到期。

先写“你的作答”，代码题还需写实际重做命令和结果，然后展开答案。对照自己的原回答选择独立答对、需要提示或仍然不会。展开后原回答不可修改，避免把看过答案后的理解冒充独立回答。

间隔按 UTC 日期：失败 1 天、提示 3 天、连续独立答对 3/7/14/30 天；失败或提示重新开始连续计数。一张卡一天最多记录一次。暂停不会删除历史；恢复也不会重置历史。来源移入回收站后不能继续评级，恢复来源后再使用。来源更新会显示核对提醒；本版不自动改写已保存的题目和答案，保存前应检查准确性。

## 第三次：按结果安排今日任务

“今日任务”依次考虑到期复习、最新练习的阻塞/漏检、尚未完成的实践主线。可调整 0–180 分钟预算，最多展示三项，也可用“上移”改变当前顺序。短于建议时长表示先做一部分，不承诺这段时间足够完成任务。

调整不写入正式日课、不自动标记掌握。完成后自行记录日课和证据。跨日或其他设备更新后，点击“获取最新版本”；没有后台定时任务和通知。

## 保存失败时

- SHA 冲突：保留当前输入，点击“获取最新版本（保留输入）”，核对历史后再提交。
- 网络中断：可能已提交但响应未收到，先获取最新版本核对。练习请求 ID 防止同一份请求重复创建。
- 关闭或浏览器刷新：未提交输入只在内存中，会丢失；不使用 localStorage 做正式数据或草稿持久化。
- 容量达到 100 次练习、100 张卡、每卡 60 次历史或 512 KiB 时停止新增，历史不会被裁剪。扩容需要另行规划。

练习只使用隔离教学服务与合成数据；不向生产网站发起测试、压测或故障注入。
