## G1 · 连续学习与检索

1. 今日任务增加“均衡学习 / 集中复习”。纯推荐函数保留原复习优先作为兼容模式；界面默认均衡模式，在有实践候选且预算允许时优先给实践留一个位置，再按原到期顺序补充，最多三项、总预算不超限。时间仍是投入预算，不承诺完成。模式与调序只影响当前查看，不改正式进度或复习间隔。
2. 训练页的练习记录、创建复习卡及未提交作答提供显式保存/恢复/清除本机草稿。默认不自动持久化。草稿经过独立 schema、大小、有效期和凭据格式拦截；恢复由用户确认，不覆盖远端状态，不自动提交。已展开答案的作答恢复后仍锁定原回答；按卡片、学习日和来源版本隔离。成功提交只清除对应本次草稿，其他表单不受影响。
3. 脏表单提示离开/刷新风险；站内链接离开可取消，浏览器原生刷新提示受平台能力限制。浏览器前进/后退、崩溃恢复依赖用户显式保存草稿，不操纵历史栈伪造拦截。保持原 SHA 冲突、失败保留输入和幂等请求 ID。
4. 搜索保留原权限过滤和匹配语义，增加真实命中上下文、安全文本高亮、内容类型筛选与中文类别标签。不把搜索字符串注入 HTML/正则，不建立新持久索引，不把隐私记录交给客户端后才过滤。

## G2 · 演武台：注册用例设计

- 仅基于现有 beginner-api-lab 注册契约与 E1–E3，不新增被测服务、课程、题库或在线运行器。
- 在训练台增加“用例设计”入口：契约摘要、可编辑用例（类型、前置、输入步骤、预期状态码、响应、数据状态、设计理由）、缺项提示和延迟展开的检查提示。
- 每条提示针对填写后的用例；显示“填写情况 / 对照提示”，不把填满字段或阅读提示标为通过，不生成整份参考答案。
- 最多 20 条用例。设计转为可读 Markdown，所有者确认公开仓库后通过既有作业创建 API 提交到 Project 0，保留普通作业的查看、迭代与编辑方式。不新增正式 schema/数据库，不直接改写仓库真实内容。
- 提交成功显示作业与 commit，提交中锁定、失败保留输入。响应不确定时先核对作业列表再决定重试，不自动重复 POST。
- 未提交草稿使用 G1 同一机制；不能把正式作业缓存到 localStorage。原作业页仍可继续修订。

## G3 · 证据核验与失败对照

### 只读核验

- 所有者明确点击才核对已保存练习；输入仅为已存在尝试 ID，不接收任意外部 URL。
- 服务端从 GitHub 正式训练档案取出 commit/CI URL；目标固定为本仓库、指定 Python beginner lab 工作流。不执行代码，不触发/rerun workflow，不下载或执行报告附件，不暴露原始日志或密钥。
- 有界读取运行元数据、同次 attempt 的作业/步骤与产物元数据，必要时读取固定路径的工作流文本。每次请求有请求数、返回条数和时间限制；所有者鉴权、同源限制、private no-store、进程内限流，禁用自动重试。无令牌时允许公开元数据读取；权限或配额不足如实显示，不能改部署权限。
- 分开呈现：CI 链接来源、运行声明的提交是否一致、指定工作流是否一致、运行/步骤状态、是否声明个人测试命令、报告是否仍可用。工作流名称、绿灯与产物名称不等于报告内容已验真。
- 本轮不把任何结果升级为“已掌握”，不修改 self_reported 或旧成绩。个人基线、三项故障的实际断言与测试独立性仍需原始报告和人工核对。示范 selfcheck 的通过明确标为示范。
- 核验结果仅本次内存展示；正式记录仍在 GitHub，不将临时 Actions 产物当第二个持久数据源。通过 API mock 和内存 fixture 验收，不修改真实尝试。

### 失败到修复

- 在既有训练档案中由用户选择两次尝试对照正常基线、三项故障、自报复盘与 commit/CI 链接，保留时间方向与来源标记；一项或零项时明确空态。
- 只把 self_reported 的变化称为“自报变化”；不能推断哪次是根因修复、代码质量或独立完成。GitHub compare 链接用于查看实际差异。
- 对照内容可经用户编辑、确认后使用既有排障 API 保存为普通排障记录；随后使用原“加入复习”入口。分类采用现有标签，用户选定，不用算法从正文猜根因。不批量创建或自动生成复习卡。

## 视觉方案

受众是学习 Python/pytest 的测开初学者；单页任务是根据契约写预期、查看证据、带着失败再次练习。

沿用 R3–R6：暖纸 #fffcf6、浅纸 #f7f3ea、墨褐 #1f1b15、赭金 #79561e、玉绿 #42624b、警示 #8f382b。艺术字仅既有首屏；章节标题用现有 Noto Serif SC/宋体回退，操作和正文用 Noto Sans SC/微软雅黑，代码与版本号沿用等宽字体。正文 16px / 1.75，辅助 13–14px，最窄 320px 不溢出。

识别性元素是“契约 → 我的预期 → 运行证据”的对照面板。没有新 hero、大图、字体资源、动效库或依赖。状态同时有文字；展开和状态切换轻微反馈，尊重 reduced-motion。

```text
训练页：今日任务 | 练习验收 | 复习队列 | 用例设计 | 失败对照
        全局：读取/提交状态 · GitHub 版本提示

用例设计：契约摘要     | 用例 1 [类型]
          验收要求     | 前置 / 输入与步骤
                       | 我的预期：状态码 / 响应 / 数据变化
                       | 设计理由 → 填写后展开检查提示
                       | 添加用例 · 查看 Markdown · 提交为作业

失败对照：选择较早尝试 | 选择较晚尝试
          基线 / 三项结果 / 自报复盘逐项对照
          commit 与 CI 来源 · 编辑排障草稿 → 提交 GitHub

手机：上述区域按阅读顺序纵向排列，字段不挤成宽表格。
```

设计复核：将复杂能力图谱收敛为真实用例字段与证据对照；表单的填写状态不做“通关印章”，避免装饰暗示已验收。沿用现有页面布局和普通编辑器，不建立重复学习中心。

参考交互：[Exercism](https://exercism.org/docs/using/solving-exercises/using-the-online-editor) 的同屏说明/操作/结果，[GitHub Skills](https://skills.github.com/quickstart) 的仓库内分步学习，[Playwright Trace Viewer](https://playwright.dev/docs/trace-viewer) 的前后对照。只借鉴组织方式，不复制素材。

## 安全、数据与回退

- GitHub Repository 是唯一正式数据源。所有正式写入只经原 owner、同源、schema、公开确认、凭据拦截及 SHA/创建保护。保留原服务行为和旧数据格式；新页面只创建用户明确提交的新作业/排障。
- 禁止正式数据本地落盘、localStorage/IndexedDB 后备存储。只允许经用户操作保存的未提交草稿；7 天有效期、限定版本/键/大小，不存读取快照、评级历史、核验结果或凭据。本地草稿不是私密保险箱；共享设备建议不保存。
- 测试全部用内存仓库、合成记录与 mock CI，真实学习数据不参与写入。不要读取本机 Git 凭据用于应用运行；此前 PR 说明授权不扩展为应用密钥授权。
- 不改 OAuth、安全策略、env、依赖、课程顺序、知识点 ID、复习评分/间隔，不自动记录学习完成，不触发远端练习或生产压测。
- 不改旧测试断言来迎合新代码；对明确新增的推荐模式增加测试，兼容旧模式。禁止 skip/fixme、删除旧测试、超大 timeout、等待所有离屏图片 decode。
- 若遇到脏工作区、远端分支变化、需新权限/密钥、真实内容迁移、任意代码执行或不可恢复操作，停止对应动作并报告，不借本书自动扩权。
- 新增功能可通过移除新增 UI/只读 API 回退；已明确提交的普通作业/排障仍由原系统阅读，不需反向数据迁移。
