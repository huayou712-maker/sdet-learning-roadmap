# 展示图片清晰度修复

## 本轮边界

从 main 的 2adb7ca 建立 fix/responsive-hd-images。只修复现有界面配图的交付尺寸与压缩质量；不更换题材，不改变布局、动效、登录配置或正式学习数据，不自动合并或手动发布。

保留现有纸色 #eef0e9、墨色 #233c35、玉色 #44685a、赭金 #9b712d；标题/正文继承楷体，代码继承等宽字体。主视觉与书卷、关隘图片保持原构图。未调用生成图片工具：原素材已具备足够像素，重新生成不能解决 sizes 声明错误。

## 根因与修复

- 原素材：hero 与透明水墨为 1672×941，七张笔记/项目 WebP 为 1448×1086。共九张文件，全部保留，没有插值放大或额外图片依赖。
- 原笔记图不论用途都声明为 100–120px，导致空状态大图和笔记网格下载小图后被放大；项目图 300px 的默认值也不适合作品集的大封面。
- 现在 Thumbnail 必须明确传入展示位置 slot；尺寸集中在 components/dashboard/image-sizes.ts，区分列表、空状态、笔记网格、项目网格、首页精选、作品集大封面和单/多项目卡片。
- Hero 的手机最小取图宽度考虑 290px 高容器下 object-fit: cover 的裁切；装饰图按包含面板内边距的完整区域取图。Next/Image 继续生成响应式 srcset，自适应设备像素密度。
- 展示图采用 quality=85，Next 配置明确允许 75/85；保留懒加载、图片优化与尺寸上限，不把全部图片强制切成原图直出。主视觉改用当前 Next.js 支持的 preload。

## 验收方法

- 单元测试检查全部九张源图至少 1400px 宽、900px 高；大幅笔记/项目位置不能复用列表小图配置。
- 新增 E2E 以全新的浏览器上下文检查 1440/1024/390px、DPR 1/2，避免缓存中的大图掩盖错误 sizes。
- 先滚动使图片进入视口，再检查 complete/naturalWidth；读取 currentSrc 对应响应的真实像素数，必须满足显示尺寸×DPR，并计算 cover 裁切需要，最高以源图实际像素为限。naturalWidth 会受 srcset 密度校正，不能把它直接当成下载文件宽度。
- 检查单张优化后的响应不超过 600KB，兼顾加载体积。原有图片验收不删除，不增加超时、不 skip，不等待视口外所有图片 decode。
- 合成空笔记状态在隔离 E2E 初始状态下先执行；随后用带标记的测试笔记和独立 project-5 覆盖实际列表、网格与作品集。不会向真实 GitHub 内容分支写测试记录。
