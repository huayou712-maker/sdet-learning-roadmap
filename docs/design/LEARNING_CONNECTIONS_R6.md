# 江湖学习关联 R6 · 执行边界书

## 目标与范围

为测开初学者连接“接下来做什么、做成什么、已有笔记用在哪里”。本轮只做六站功法长卷与笔记学习关联，继续 `feat/jianghu-art-ui` / Draft PR #7。先写本方案，再实现、回归并核对远端 CI；不自动合并。

不新增江湖悬案、实验包、课程、AI 评分、成长算法或作品集系统。上述构想留待本轮验证后单独定范围。

## 设计契约

- 保留已确认的江湖视觉：暖纸 `#fffcf6` / `#f7f3ea`、墨褐 `#1f1b15`、赭金 `#79561e`、玉绿 `#42624b`，状态同时使用文字。
- 艺术字体仍限首页首屏，不再重做字体。页面/章节标题用现有 Noto Serif SC 与本地宋体回退，正文/操作用 Noto Sans SC 与微软雅黑回退，真实站序用现有等宽字体。正文 16px 起、1.75 行高，辅助说明 13–14px，不以大段字距营造江湖感。
- 识别特征是一条赭金路线脊线与真实六站序号。桌面左侧短导航、右侧原生可展开章节；手机恢复纵向长卷，不横向挤压六个选项。
- 默认展开现有推荐站，所有站自由访问。定位任意 `#task-*` 时展开对应章节；保留原 summary 键盘交互，允许多站对照，不制造通关锁。
- 章节保留原任务标题、摘要、交付、全部验收项、真实知识点及指南链接。只新增最多三条可见关联记录，不把关联当成自动验收。
- 笔记正文末尾增加“这篇笔记，用在何处”：关联实践任务、知识点及最多五条记录。旧的仅同阶段笔记列表撤下，目录仍在侧栏，侧栏提供跳到关联的入口。专注模式同时隐藏关联区，退出恢复。
- 动效仅为展开内容轻微淡入与链接焦点/悬停反馈；`prefers-reduced-motion` 禁用新动画，无循环动画、视差或新媒体。

```text
路线：页面标题 / 六站实践说明
      短导航 + 脊线  |  01 原任务标题 · 自评 / 证据说明
      01 → 06      |     交付 → 验收 → 对应知识点
      当前建议标识  |     关联记录（来源标签）/ 原指南入口
                    |  02 … 06 原生折叠章节
      十阶段参考目录（原功能与筛选不变）

笔记：原目录 / 正文 / 元信息
      正文末尾：这篇笔记，用在何处
      [对应实践与知识点] | [相关笔记、作业、项目、排障手记]
      专注阅读：隐藏侧栏和末尾关联，保留原文与退出入口
```

取舍复核：不画 150 节点的装饰性知识图谱；用可以进入原页面的链接表达关系。不复制出第二套课程，不用伪进度、徽章或模板大卡片填充空数据。

## 关联规则（展示派生，不写回）

1. 服务端先按现有 `!deletedAt && (owner || showInPortfolio)` 规则过滤，再计算关联。客户端只收到必要的标题、类型、内部链接和理由，不收到全文、SHA 或未展示记录的 ID/数量。
2. 知识点只接受当前 roadmap 中实际存在的 ID。来源分为笔记/记录的 `topicIds` 标注，以及现有 progress 中明确登记的同类型、同 ID 证据，两者分别标明。
3. 路线每站从这些明确的知识点关系选最多三条：已登记证据优先，其后标注关系；同级按更新时间降序、类型/ID 稳定排序。记录去重，排除每日学记，不猜测标签/正文含义。
4. 笔记以共同真实知识点关联其他笔记、作业、项目或排障手记。若历史元数据已有 `projectId`，仅在该项目本身可见时使用同项目关系。最多五条；知识点关系优先，其次同项目，再按时间稳定排序，不做多跳推断。
5. 没有明确记录关系时，最多展示三条同阶段笔记，明确标注“同阶段参考 · 未建立知识点关联”。完全为空时提供已有路线/笔记入口，不填造记录。
6. 访客路线的 progress 展示副本移除不可见/已删除记录的证据引用，避免经 RSC 暴露 ID。保留公开 commit 引用和原 completed 状态；owner 的原始进度与保存表单不变。副本不写回 GitHub，不影响推荐规则。

## 硬边界与停止条件

GitHub Repository 仍是唯一正式数据源。不得把正式记录保存到本机、localStorage、IndexedDB 或新增数据库；本轮连新的浏览器持久化也不增加。开发代码、方案和隔离合成测试产物不属于正式业务记录。

不得修改课程/任务/知识点 ID、顺序、学习数据、进度与推荐算法、复习规则、训练 schema/service/API、OAuth、权限策略、GitHub Adapter、CRUD、SHA 冲突保护、Markdown 安全、凭据拦截、限流、环境变量或部署配置。不得引入新依赖、字体、媒体资源或未经批准的外部服务。

新增只读选择器可以放在 `lib/content/learning-connections.ts`，作用仅为显示裁剪与明确关系计算。权限裁剪只接入本轮页面，不宣称替代 API 层权限或完成全站安全审计。

若实现需要新增存储、改正式数据/认证、变更课程，停止该项并报告，不借“自由发挥”扩大授权。若 PR 已合并或分支有他人更新，先检查并调整，不覆盖他人工作。

- 原六站、150 知识点、顺序、全部验收与原链接保留；原测试不删、不 skip/fixme、不放大 timeout。
- 新测试覆盖确定性关系、去重/上限、未知 ID、同阶段降级、不同类型相同 ID、私有/删除记录以及原始输入不变。
- 匿名/owner 的真实页面、SSR/RSC 可见性、直接 hash、键盘、前进/后退、原生章节 HTML 在无 JS 时仍可展开、320/390/1440px、reduced-motion、专注模式可逆。Next.js 整站的流式外壳仍依赖 JavaScript；无 JS 验收针对真实 SSR 章节片段，不承诺整站离线或无 JS 可用。
- 实际浏览器截图核对字体、留白、长标题、空态、无横向溢出；不靠等待所有离屏 lazy 图片 decode。
- 浏览行为不产生业务写请求或浏览器持久化，不改变 progress API 返回值。
- lint、typecheck、unit、build、完整 E2E、原 Python 入门回归全部通过后才提交并推送同一 PR；核对新提交对应的 GitHub Actions 与 Vercel，不引用旧提交的绿灯。
