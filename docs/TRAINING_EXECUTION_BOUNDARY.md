# 个人测开训练闭环：执行边界书

## 1. 授权与交付

用户授权：在现有学习项目上写明执行边界，并严格依照边界实施。目标是完成一次“独立练习 → 记录检出与漏检 → 再次复习 → 推荐下一步”的最小闭环。

基线：main 的 f550882；开发分支：feat/learning-training-loop。工作只发生在功能分支。通过验证后提交代码并创建面向 main 的 PR；不自动 merge、不直接推送 main、不手动发布、不修改 Vercel/OAuth/环境变量。不使用真实学习数据做写入验收。

## 2. 本轮只做三个增量

1. 练习验收台：只覆盖现有 beginner-api-lab 注册 API。记录独立测试的 commit、正常实现结果、三种故障检出结果、复盘和可选 CI 链接。验证指定 commit 中存在独立测试文件；结果仍明确标为“学习者自报，未自动验真”。CI 链接仅保存，不代表已核验 CI 或能力。示范测试不计个人成果。
2. 复习队列：从现有未删除的笔记或排障记录手动创建问题与参考答案；先作答再看答案，再选择独立答对/需要提示/仍然不会。代码类必须填写重做证据。每条来源最多一张卡；允许暂停/恢复，保留历史，不提供永久删除。来源删除或不存在时禁止复习，不清除历史。
3. 今日任务：在 /training 内按“到期复习 → 最新练习的阻塞/漏检 → 当前主线”给出解释明确的建议；支持临时调整可用时间和推荐顺序。建议不自动写成日课、不自动打勾、不推断能力等级。

不做 AI 教练、自动出题/评分、在线代码运行器、自动拉取或执行提交代码、新业务练习包、排行榜、段位、社交、全站 UI 重构、自动通知或后台定时任务。保留全部现有页面和稳定知识点 ID。

## 3. 数据与安全边界

- GitHub Repository 是唯一正式数据源；新增状态只写 content/training/state.json，复用现有 GitHub Adapter。无文件时只返回空状态，GET 不创建文件。代码中不内置真实成绩，不修改 data/progress.json 或既有 content 记录。
- 所有新增写入必须所有者身份、同源请求、严格 schema、公开仓库确认、凭据拦截和文件 SHA 并发保护。失败保持表单输入；冲突后手动获取最新版本再重试，不覆盖他人提交。
- 训练详情只向所有者提供；公开仓库中的原始文件仍可见，界面权限不是保密。提示不可提交 Token、隐私或真实业务数据。
- 不向浏览器发送密钥，不读取/复制部署密钥，不改变旧鉴权或安全防护。只支持当前仓库的完整 commit SHA 与限定独立测试路径；CI URL 只接受本仓库 GitHub Actions 运行链接。
- 草稿和临时计划仅在组件内存中；本轮不新增 localStorage/IndexedDB/本地正式数据后备。测试仅使用内存仓库及已有隔离 E2E Adapter。
- 状态读写上限 512 KiB；最多 100 次练习、100 张复习卡、每卡 60 次复习。超限明确报错，保留原数据，暂停扩容直到用户另行授权；不自动丢弃旧记录。
- 复习采用可解释的简单规则：首次到期为创建当天（UTC）；仍然不会 1 天、需要提示 3 天，独立答对按连续独立成功次数取 3/7/14/30 天。失败或提示重置连续计数。这是初版产品规则，不宣称最优记忆算法。一天最多提交一次评级，重复请求与旧版本冲突不得重复记分。

## 4. 界面约束

对象：用 Python/pytest 入门的单个学习者。页面任务：看清当前训练、提交依据、再次验证。

沿用现有楷体标题、正文与等宽代码，以及纸色/墨色/玉色/赭金 token；不引入字体、图片、依赖或动画库。布局采用“任务正文 + 验收栏”，手机收为单列。识别性元素是三项故障检出对照，颜色外还有文字标签。

采用 /training 的今日/练习/复习三个导航入口，共享提交结果提示。键盘可达、可见焦点、表单标签、禁用/错误/空态、reduced-motion 与 390px 手机视口必须验证。复用已有风格而非重做首页大图；重点交互为答案展开与提交反馈。

## 5. 阶段门禁

| 阶段 | 内容 | 进入下一阶段的必要条件 |
|---|---|---|
| G0 | 写边界书，建立独立分支 | 文档先提交；工作树无用户遗留改动 |
| G1 | 练习状态、校验、GitHub 写入与 API | 新增针对性单元/安全测试通过；覆盖读不写、鉴权、同源、凭据、非法字段、SHA 冲突、无效代码证据 |
| G2 | 复习状态转换与推荐规则 | 针对性测试通过；覆盖来源失效、重复/越界、UTC 跨日、间隔、暂停、排序/预算、不改旧进度 |
| G3 | 页面与现有入口集成 | 新增浏览器流程通过；包括刷新持久化、冲突保留输入、手机无横向溢出、匿名无写入口 |
| G4 | 完整回归与交付 | lint、typecheck、全部单元测试、build、全部 E2E、Python lab 测试及 selfcheck 全部通过；检查差异后提交 PR，核对 CI |

测试失败先修复；不得 test.skip/fixme/删测试/扩大 timeout/降低旧验收。图片继续按实际可见资源验收，保留 Next/Image lazy-loading 兼容方式。不得为测试修改真实业务规则。截图只使用合成状态。

## 6. 停止与变更机制

发现会覆盖用户未提交改动、需要真实密钥/权限、须扩展上述业务范围、需要破坏性数据迁移或生产写入时停止相应动作，说明阻碍并请求方向。不得通过改写本边界书降低门禁。事实错误可更正并记录原因；范围扩张须重新获准。

本轮终点：最小闭环及回归通过、代码提交 PR、报告 CI 与未验证事项。不声称用户已经完成练习，不将网页上线状态等同于 PR 已通过，不自动合并。
